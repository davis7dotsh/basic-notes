# search eval fixtures
All notes, names, companies, amounts, hosts and credentials here are synthetic and made up for the eval; any resemblance to real people or setups is coincidental.
- `notes/<slug>.md`: 95 synthetic personal notes, plain Markdown, no frontmatter. Title = first non-empty line (`# heading`, plain line, or `- bullet`).
- `queries.json`: array of `{ "q", "expect": "<slug>", "category" }`, category ∈ `exact_title | fuzzy_title | code | fulltext | semantic`.
- `semantic` queries share no content words/stems with their target; `code`/`fulltext` terms appear only in the target's body, not its title.
- `queries-edge.json`: robustness set (the harness injects `edge-crlf`, `edge-long`, `edge-image-only` and its reference-style twin `edge-image-ref`). `code_literal` (identifier-ish queries whose literal must beat title/word matches), `crlf` and `long_note` (expect `edge-crlf` / `edge-long`, notes the harness injects: CRLF line endings, and a 435k-char note with a sentinel at the end), plus negatives: `none` (gibberish/unrelated, must return nothing), `reject` (`reject` must not be in the top `top`), `lookup_extra` (an exact rare-token/identifier lookup: every hit must be in `allow`, no semantic look-alikes riding along) and `image_only` (`edge-image-only`, a note that is just a pasted screenshot, must never surface). Negatives report a false-positive rate.
- `queries-negative-holdout.json`: fresh `none` negatives written after the semantic floor was calibrated (not used for tuning).
- `queries-multiterm.json`: multi-term queries whose target matches several terms on one line (`multi_term`, from council reviews; `multi_term_guard` written before tuning), plus floor checks: `none` (incl. half-noise queries like `waffle recipe friday r3`), `allow` (every hit must be one of these notes — e.g. a flood of single letters + "coffee" must behave like "coffee"), and `max` (at most this many hits: middling-similarity queries mustn't admit a dozen look-alikes). `short_concept`: short concept queries from council reviews ("subscriber growth").
- The harness also checks empty-query recents order (pins, then last touched, frecency only on near-ties). `--probe FILE` runs one query per line and prints hit counts (gibberish sweeps).
